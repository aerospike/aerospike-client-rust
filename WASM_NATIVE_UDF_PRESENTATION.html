Aerospike server · branch wasm

Two Engines
Inside asd

Aerospike had one UDF language. It now has three: Lua, WASM compiled ahead of time, and native shared objects loaded from the config file. Every number in this deck was measured, in the same run, against Lua as the reference.

mod-wamr · mod-native aerospike-udf-sdk-wasm · aerospike-udf-sdk-native 45× Lua on compute 1.24× on aggregation
Why it was tractable

The server already had a language abstraction

WASM and native are additive. as_module_hooks — destroy, update, validate, apply_record, apply_stream — already existed, and mod_lua was simply one implementation of it.

The dispatch fact that shaped everything

udf_def.type is the operation (AS_UDF_OP_KVS), not the language. The language never crosses the wire at apply time, so dispatch is by the language recorded against the file name at registration — udf_cask_get_lang().

One choke point, not three ternaries

udf_cask_module_for_file() resolves language→module once; udf.c and aggr.c call it. Adding the third language made dispatch simpler than the two-language version it replaced.

WASM · engine selection

Two engines were built, and one was deleted

wasmtime (Rust, via a C shim, then pure Rust) and WAMR (pure C). They were measured side by side on the same workload, and the loser was removed rather than kept as an option.

WASM · tiers

Tier facts that decide a deployment

AoT dominates

The LLVM JIT puts libLLVM inside asd and still runs 2× slower than AoT. AoT needs wamrc only to produce files; asd links no LLVM at all.

Fast JIT is x86-64 only

fast-jit/cg/ has exactly one code generator. The CMake now hard-fails instead of quietly building an interpreter that would later be benchmarked as a JIT.

The interpreter is the silent fallback

It is only 1.8× Lua, and it is where you land whenever wamrc is missing or an .aot is stale. Hence the wamr: executing in <mode> mode log line — operationally necessary, not decoration.

WASM · the ABI decision

No msgpack anywhere

Typed natives return scalars in registers; collections cross as handles into a per-call as_val* table. The guest therefore needs no allocator at all.

Where the per-call cost actually lives

Roughly 8 µs over Lua, dominated by instantiation (~4 µs) and the guest's first allocation (~5 µs) — not the host boundary. That is why removing the C shim was a clarity refactor that changed nothing measurable, exactly as predicted beforehand.

WASM · stream UDFs

Aggregation was hardcoded to Lua

aggr.c pointed at &mod_lua: record UDFs dispatched by language, aggregation did not. WASM aggregation is one instance per stream, because a guest otherwise gets a fresh instance per call and accumulators need somewhere to live.

The bug a small test could not find

A record read from the istream is owned by the stream — istream_read closes the previous one, so destroying it in the module is a double free. A 50-record test passed with that bug in place. It took 100,000 records to fault.

Handles borrow from a released record

They must be released between records, or 1000 records overflow a 256-slot table: mod_wamr_ctx_next_record.

Reached by query(), not query_aggregate()

query_aggregate runs its final reduce in client-side Lua, which WASM cannot join. WASM returns one partial per node and the caller combines.

Native · the security boundary

Registration is config-only, and that is the point

A native module runs in the server's address space with its privileges. Installing one is an operator's act, never a client's — so it is declared in aerospike.conf and nowhere else.

mod-native {
    module summary {
        path /home/khosrow/sdk-native/examples/summary/target/release/libaerospike_udf_example_summary.so
    }
}

Three independent refusals

udf-type=NATIVE is absent from is_valid_udf_type; udf-put refuses a Lua/WASM name whose base name collides with a configured module (silently losing the dispatch would be worse than an error); validate refuses unconditionally as a second lock.

dlopen flags are a correctness question

RTLD_NOW | RTLD_LOCAL, never dlclose, and never RTLD_DEEPBIND — the server uses jemalloc, and DEEPBIND would bind the plugin to a different malloc, making every cross-boundary pointer a cross-allocator free.

Native · aggregation design

Four shapes, one trait

The trait

Fold, Emit, heap_used() (so an operator ceiling applies as well as the plugin's own limit), merge, finalize once on merged data.

The shapes

Filter, chunked collect, reduce. The rule: emit output values or partials, never both — they share one stream and a client cannot tell a mixture apart.

Where it hooks

query_job.c:203 already calls the slice function once per thread with a buf_builder in hand, so the accumulator is per thread: no mutex, no response-path change.

out.record(rec) is genuinely allocation-free — the server already has the record. out.value(v) is not, because building v allocates server-side. The second is never described as free.

Native · the same two functions, twice

C writes the type checking; Rust has already done it

The Rust example is deliberately the same functions as the server tree's C example, so the two compare line for line. Per record they cost the same — one host call — and that is the point: the difference is entirely in what you have to write.

Record UDF — C46 lines

static int32_t
increment(as_native_ctx* ctx, as_native_rec* rec,
    const as_native_value* args, uint32_t n_args,
    as_native_value* result)
{
    int64_t by = 1;

    if (n_args == 1) {
        if (args[0].type != AS_NATIVE_TYPE_INT) {
            fail(ctx, "argument must be an integer");
            return AS_NATIVE_TYPE_MISMATCH;
        }
        by = args[0].u.i;
    }

    int64_t n = 0;
    int32_t rv = H->rec_get_int(rec, NAME("n"), &n);

    if (rv == AS_NATIVE_TYPE_MISMATCH) {
        fail(ctx, "bin 'n' is not an integer");
        return rv;
    }

    bool existed = H->rec_exists(rec);
    n += by;

    if ((rv = H->rec_set_int(ctx, rec, NAME("n"), n))
            != AS_NATIVE_OK) {
        fail(ctx, "could not set bin 'n'");
        return rv;
    }

    rv = existed ? H->rec_update(ctx, rec)
                 : H->rec_create(ctx, rec);
    if (rv != AS_NATIVE_OK) {
        fail(ctx, "could not commit");
        return rv;
    }

    result->type = AS_NATIVE_TYPE_INT;
    result->u.i = n;

    return AS_NATIVE_OK;
}

Record UDF — Rust5 lines

udfs! {
    /// Add `by` to bin "n"; `by` defaults to 1.
    fn increment(rec: &Record, by: Option<i64>)
        -> Result<i64>
    {
        let next = rec.get_int("n")?.unwrap_or(0)
            + by.unwrap_or(1);

        rec.set_int("n", next)?;
        rec.write()?;          // read, modify, stage, COMMIT

        Ok(next)
    }
}

Aggregation — Rustone impl block

impl Aggregation for Sum {
    const NAME: &'static CStr = c"sum";

    fn configure(&mut self, args: Args<'_>) -> Result<()> {
        self.bin = args.get(0).as_str()
            .ok_or_else(|| Error::msg("bin name"))?
            .to_string();
        Ok(())
    }

    fn accumulate(&mut self, rec: &Record, _out: &Emit)
        -> Result<Fold>
    {
        // one host call per record, nothing else
        if let Some(v) = rec.get_int(&self.bin)? {
            self.total += v;
        }
        Ok(Fold::Continue)     // never full: nothing grows
    }

    fn merge(&mut self, other: &Self) {
        self.total += other.total;
    }

    fn finalize<'c>(&mut self, _ctx: &'c Ctx)
        -> Result<Value<'c>>
    {
        Ok(Value::int(self.total))
    }
}

Aggregation — Csix functions + state struct

typedef struct sum_state_s {
    int64_t  sum;
    char     bin[16];
    uint32_t bin_len;
} sum_state;          // POD: allocates nothing, ever

static int32_t
sum_accumulate(as_native_ctx* ctx, void* state,
    const as_native_rec* rec, as_native_emit* out)
{
    sum_state* s = (sum_state*)state;
    int64_t v;

    // one host call per record, nothing else
    if (H->rec_get_int(rec, s->bin, s->bin_len, &v)
            == AS_NATIVE_OK) {
        s->sum += v;
    }

    return AS_NATIVE_OK;   // never full
}

static int32_t
sum_merge(as_native_ctx* ctx, void* dst, const void* src)
{
    ((sum_state*)dst)->sum +=
        ((const sum_state*)src)->sum;
    return AS_NATIVE_OK;
}
// + sum_init, sum_to_partial, sum_from_partial, sum_finalize

udfs! checks arity and types before the body is entered, so the four fail() branches in the C version have no Rust counterpart to get wrong. Both land within 3% on the benchmark — 33 ms against 34 ms — so this is ergonomics, not performance.

The decomposition the table cannot show

Running the same native aggregation against itself, dumping at Lua's rate or not at all: 4 partials in 31 ms against 4168 partials in 48 ms. So ~1.5× is shipping 4 partials instead of 4168 and ~2× is the engine. They multiply; neither alone is the headline.

Scale check

End to end, 39.6 ms native against 48.9 ms Lua is 1.24–1.31×. Smaller than "one indirect call per record" suggests — and that is the finding. A plain scan of the same rows costs 313 ms, six times the whole aggregation.

Most of the gap is one missing accessor

Lua's bytes has integer getters and no float getter, so a packed vector must be copied out as a Lua string and decoded by string.unpack: +3,240 ns of 7,873, with no native counterpart at all — the plugin measures the particle where it lies. Strip the decode and orderby puts the engine itself at 7.8× (199 against 1,557 ns), which is the honest figure for a Lua call, a closure and a table state.

And the obvious fix is measured to be worse

Adding bytes.get_float_le(b, i) is exactly the topk_scan row: one call per element instead of one per vector, and it is 1.6× slower than building a 768-code format string. A per-element accessor would make the natural implementation slower than the workaround it replaces. What would pay is a bulk decode, or a distance primitive.

At this size the engine decides the architecture

Server-side Lua (394 ms) is 3× slower than shipping all 146 MB to the client and sorting in Rust (125 ms); the plugin is 7× faster than that. Same query, same data, opposite conclusion about where to compute. Read it as the client's best case — a local bridge and a fast laptop — which only sharpens the point.

Traps

What actually cost the time

  • cf_malloc is a macro under -DENHANCED_ALLOC, so no such symbol exists to call from another language — and a module built without that define compiles fine standalone, failing only when asd links.
  • A hook must return 0 and put the failure on the as_result. A non-zero return makes udf.c overwrite the message using mod-lua's error map, so a missing wasm module reported "Mod-Lua user path not found".
  • cargo:rerun-if-changed on a directory does not fire for edits to files inside it. The first perturbation experiment rebuilt nothing and looked like success.
  • Deleting .d files does not force recompilation — it removes dependency tracking. Stale objects kept an old cfg.h layout and n_namespaces read at the wrong offset ("too many namespaces"). Delete target/<plat>/obj instead.
  • Link order is single-pass: libmod_wasm_rs.a must precede libaerospike-common.a, because no server object references as_buffer_init.

Deploying it · 2026-08-19

Standing the SDK server up on the Linux VM

Why it would not start

mod-native aborts startup when any configured module is missing — correct, given config-only registration, but one unbuilt .so presents as a broken server. make example in modules/mod-native fixed it.

Why WASM was quietly slow

1510 cache files compiled by a different WAMR failed with unknown binary version — 755 silent interpreter fallbacks, i.e. 1.8× Lua where 45× was expected.

wamrc needs LLVM 16+

Not 15, as the Makefile default still says: undefined reference to LLVMGetVersion. Ubuntu 22.04 has no llvm-16+ in its repos.

# arm64 mac, arm64 VM: build natively in a jammy container (glibc 2.35 matches),
# then bundle the one library beside the binary so the VM needs no LLVM at all.
podman run --rm -v .../aerospike-server:/src ubuntu:22.04 bash -c '
  /tmp/llvm.sh 18 && apt-get install -y llvm-18-dev
  cd /src/modules/mod-wamr && make wamrc LLVM_DIR=/usr/lib/llvm-18/lib/cmake/llvm
  cp -fL /usr/lib/aarch64-linux-gnu/libLLVM-18.so.1 target/Linux-aarch64/bin/libLLVM-18.so.18.1
  patchelf --set-rpath "\$ORIGIN" target/Linux-aarch64/bin/wamrc'

Result: wamrc 2.4.3 runs on the VM, AoT-compiles a module in ~460 ms, zero interpreter fallbacks, six native modules loaded, and from the Mac 10/10 wasm tests plus 6/6 native summary tests pass.

Deliberately not done

The edges, stated in the code

Per-node partials

Today it is a handful per node — one per query thread. Going to one needs job-finish emission, and aggr_query_job_finish closes the client connection first: a mutex on a job-level accumulator plus a response-path change, to turn four partials into one. Not worth it.

No in-server C baseline

It would need a function compiled into asd, and per-call resolution is too coarse to measure what it would tell us.

No deadline for aggregation

aggr.c passes no timer — and mod_lua has exactly the same gap, so this is a pre-existing property rather than something WASM introduced.
